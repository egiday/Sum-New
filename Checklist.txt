**Phase 1: Project Setup & Backend Foundation (Next.js App Router)**

[x] 1.1: Initialize Next.js Project Structure (App Router):
    - Use `create-next-app` with TypeScript, Tailwind CSS, and ESLint.
    - Ensure the project uses the App Router.
    - Create the `/src` directory and move `/app` and `/components` inside it.
    - Initialize `git` repository.

[x] 1.2: Define TypeScript Interfaces for Data:
    - Create a file (e.g., `src/lib/types.ts` or similar).
    - Define an `interface Poll` with: `pollId: string`, `question: string`, `options: string[]`, `createdAt: Date`.
    - Define an `interface Vote` with: `voteId: string`, `pollId: string`, `selectedOption: string`, `votedAt: Date`.

[x] 1.3: Set Up Database & Prisma (or chosen ORM/client):
    - Choose and set up a database (e.g., PostgreSQL, MongoDB Atlas, Supabase, Vercel KV/Postgres).
    - Install and configure Prisma (or the appropriate client/ORM).
    - Define Prisma schema models corresponding to the `Poll` and `Vote` interfaces.
    - Run initial migration (`prisma migrate dev`).

[x] 1.4: Implement API Route Handler - Create Poll:
    - Create a Next.js Route Handler at `src/app/api/polls/route.ts`.
    - Implement the `POST` function.
    - Accept `question: string` and `options: string[]` from the JSON request body.
    - Generate a unique `pollId` (e.g., using `nanoid`).
    - Use Prisma client to save the new poll data to the database.
    - Return a JSON response containing the `pollId`, the voting URL (`/poll/{pollId}`), and the results URL (`/poll/{pollId}/results`). Include appropriate status codes (201 on success).

[x] 1.5: Implement API Route Handler - Get Poll Details (for Voting Page):
    - Create a Next.js Route Handler at `src/app/api/polls/[pollId]/route.ts`.
    - Implement the `GET` function. It receives `params` containing `pollId`.
    - Use Prisma client to retrieve the poll `question` and `options` based on the `pollId`.
    - Return a JSON response with `question` and `options`. Handle cases where the poll is not found (404). (Do *not* return vote counts here).

[x] 1.6: Implement API Route Handler - Submit Vote:
    - Create a Next.js Route Handler at `src/app/api/polls/[pollId]/vote/route.ts`.
    - Implement the `POST` function. It receives `params` containing `pollId`.
    - Accept `selectedOption: string` from the JSON request body.
    - Fetch the poll details to validate that the `selectedOption` is one of the valid options for the given `pollId`.
    - Use Prisma client to save the vote to the database, linking it to the `pollId`.
    - Return a JSON success confirmation (e.g., `{ success: true }`) or validation error (400).

[x] 1.7: Implement API Route Handler - Get Poll Results:
    - Create a Next.js Route Handler at `src/app/api/polls/[pollId]/results/route.ts`.
    - Implement the `GET` function. It receives `params` containing `pollId`.
    - Use Prisma client to retrieve the poll `question` and `options`.
    - Use Prisma client to count the votes for each option associated with the `pollId`.
    - Return a JSON response containing the `question`, `options`, and the `voteCounts` (e.g., an object like `{ optionText: count }`). Handle poll not found (404).

**Phase 2: Frontend Development (React Server Components & Client Components)**

[x] 2.1: Create Poll Creation Page UI (`src/app/page.tsx`):
    - Implement the main page as a React Server Component (RSC) by default.
    - Use Shadcn UI components (`Input`, `Button`, potentially `Card`) and Tailwind CSS for layout.
    - Include a form structure for the poll `question` input.
    - Include inputs for `options` (start with static fields, plan for dynamic addition later if needed).
    - Add a "Create Poll" button.
    - Make this form interactive using a *minimal* Client Component (`'use client'`) only for managing form state and handling submission.

[x] 2.2: Create Voting Page UI (`src/app/poll/[pollId]/page.tsx`):
    - Implement this page using Next.js dynamic routing.
    - Fetch poll data (`question`, `options`) in the Server Component using the `pollId` from params and the API handler from 1.5 (or directly fetch if colocating data fetching logic).
    - Display the `question`.
    - Render the `options` using Shadcn UI components (e.g., `Button` or `RadioGroup`).
    - Include a "Submit Vote" button.
    - Wrap the voting options and submit button in a *minimal* Client Component (`'use client'`) to handle option selection state and the vote submission logic.

[x] 2.3: Create Results Page UI (`src/app/poll/[pollId]/results/page.tsx`):
    - Implement this page using Next.js dynamic routing.
    - Fetch poll results (`question`, `options`, `voteCounts`) in the Server Component using the `pollId` from params and the API handler from 1.7 (or direct fetch).
    - Display the `question`.
    - Render the `options` and their corresponding `voteCounts`.
    - Consider a simple visual representation (e.g., text counts, basic bars using styled `div`s with Tailwind). This page can likely remain a Server Component.

[x] 2.4: Implement Frontend Logic - Create Poll Client Component:
    - In the client component created in 2.1:
        - Manage form state (`question`, `options`) using `useState`.
        - Implement the `onSubmit` handler for the form.
        - Prevent default form submission.
        - Make a `fetch` `POST` request to `/api/polls` with the state data.
        - Handle the response: On success, display the returned voting and results links (perhaps using state). Handle errors appropriately (e.g., display an error message).

[x] 2.5: Implement Frontend Logic - Voting Client Component:
    - In the client component created in 2.2:
        - Manage selected option state using `useState`.
        - Implement the click handler for the "Submit Vote" button.
        - Make a `fetch` `POST` request to `/api/polls/[pollId]/vote` with the selected option.
        - Handle the response: On success, display a "Vote Recorded" message or redirect to the results page (`useRouter` from `next/navigation`). Handle errors.

**Phase 3: Styling & Refinement**

[ ] 3.1: Refine Styling and Responsiveness:
    - Review all pages and components.
    - Ensure consistent use of Tailwind CSS and Shadcn UI conventions.
    - Verify responsive behavior on different screen sizes using Tailwind's modifiers (`sm:`, `md:`, `lg:`). Ensure usability on mobile.

[ ] 3.2: Basic Duplicate Vote Prevention (Client-Side Indication):
    - In the Voting Client Component (from 2.5): After a successful vote submission, consider disabling the voting options/button or storing a simple flag in `localStorage` scoped to the `pollId` (e.g., `localStorage.setItem('voted_poll_{pollId}', 'true')`).
    - On component mount, check for this flag. If present, display a "You have already voted" message instead of the options. (Note: This is easily bypassed but meets MVP 'discouragement' goal).

[ ] 3.3: Enhance Results Display:
    - On the Results Page (2.3): Improve the visual display of vote counts. Use `div` elements styled with Tailwind to create simple horizontal progress bars representing the percentage or count for each option. Calculate percentages relative to the total votes.

[ ] 4.1: Prepare for Deployment:

    - Update `.gitignore` if necessary.
    - Create/update `README.md` with basic setup and deployment notes.

[ ] 4.2: Deploy to Hosting Platform (e.g., Vercel):
    - Connect the Git repository to a hosting provider like Vercel.
    - Configure build settings if needed (usually automatic for Next.js).
    - Trigger a production deployment.

[ ] 4.3: Final Testing on Production URL:
    - Thoroughly test the end-to-end flow on the live production URL.
    - Create polls, vote from different browsers/devices (including incognito/private modes), and check results display.
    - Verify basic responsiveness.
